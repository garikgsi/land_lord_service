# LandLordService

Система управления арендой и эксплуатацией недвижимости. Подготовлены
локальная среда, адаптивный интерфейс, авторизация и управление пользователями.
Предметные реестры недвижимости и расчёты пока не подключены.

Основной клиент: Tabler + Vue + Symfony API. Он же будет упаковываться
в Capacitor. Отдельные серверные страницы используют Tabler + Twig.

## Локальная разработка

Основной каталог: `/opt/homebrew/var/www/LandLordService`.
`Dockerfile` и `compose.yaml` находятся в корне проекта; конфигурация
Nginx и PHP находится в `docker/`.

Требуются запущенный Docker с Compose v2 и OpenSSL для генерации локальных
секретов. PHP, Composer и Node на хосте не нужны.

```sh
./bin/setup
```

Скрипт создаёт `.env` с локальными секретами, если файла ещё нет, собирает PHP,
устанавливает зафиксированные Composer/npm-зависимости, собирает Vue-клиент
и запускает сервисы, затем применяет миграции Doctrine.
Существующий `.env` сохраняется. Порт задаётся через `HTTP_PORT` в `.env`.
По умолчанию сервис доступен только на `127.0.0.1:18080`.

Проверка всей цепочки Nginx → PHP-FPM → Symfony → PostgreSQL:

```sh
curl --fail http://127.0.0.1:18080/api/healthz
```

Ожидается `{"status":"ok"}`.

- [Основное приложение](http://127.0.0.1:18080/): Vue, адаптивная навигация,
  светлая/тёмная тема, поиск разделов через Tom Select и календарь Standard.
- [Серверная страница состояния](http://127.0.0.1:18080/server/status): Twig
  с теми же собранными CSS-ресурсами и общей серверной проверкой БД.

Интерфейс явно помечен как предварительный. Реестры пока являются каркасом,
календарь не содержит событий. Тестовые договоры, объекты и суммы не создавались.

```sh
docker compose ps
docker compose logs --tail=100
docker compose exec php php bin/console about
docker compose stop
```

Проверки приложения и окружения:

```sh
./bin/check
```

Проверяются TypeScript и сборка Vue, тесты адаптеров frontend, зависимости PHP, DI-контейнер, YAML,
Twig, API при доступной и недоступной БД, серверный экран, конфигурация Nginx
и HTTP-ответ внутри контейнера. Тесты используют отдельную БД с суффиксом `_test`.

После изменений frontend пересобрать клиент:

```sh
docker compose run --rm --no-deps node npm run build
```

## Типы и состояние frontend

Собственные интерфейсы и типы находятся в `frontend/src/types`: `models`,
`api`, `forms`, `components`, `router` и `use`. В компонентах импортируем их
через `import type`, не объявляем модели повторно.

`frontend/src/store/auth.ts` содержит Pinia-хранилище `useAuthStore()`: профиль,
производные права и действия входа, проверки сеанса и выхода. В компонентах
свойства хранилища доступны без `.value`. В роутере передаём `pinia` явно.
Bearer хранится вне реактивного state. `store/roles.ts` экспортирует общий
`roleLabels` и список назначаемых ролей; системная роль в него не входит.

## Адаптеры frontend

`frontend/src/use` содержит интерфейсы расширений, которые используются
компонентами, хранилищами и обычными скриптами приложения.

`use/event.ts` экспортирует `useEvent()` — общую типизированную шину на
[mitt](https://github.com/developit/mitt). Все вызовы получают один экземпляр.
События и типы их данных объявляются в `types/use/Event.ts` (`AppEvents`). Для подписки используются
`on`, для отправки `emit`, для снятия подписки `off` с той же функцией-обработчиком.
В Vue-компоненте подписку снимаем при завершении его области:

```ts
import { onScopeDispose } from 'vue';
import useEvent from '../use/event';

const events = useEvent();
const onExpired = () => { /* Реакция компонента на завершение сеанса. */ };
events.on('session-expired', onExpired);
onScopeDispose(() => events.off('session-expired', onExpired));
```

Обычный скрипт тоже может вызвать `useEvent()`; Vue-контекст для этого не нужен.
Долгоживущие подписки авторизации и роутера снимаются при замене модулей в dev.

`use/api.ts` экспортирует `useApi()` — общий HTTP-клиент на fetch:

```ts
import useApi from '../use/api';
import type { User } from '../types/models/User';

const { api, request, errorText } = useApi();
const users = await api<{ items: User[]; total: number }>('/api/admin/users');
```

| Метод | Назначение |
| --- | --- |
| `api<T>(path, init?, authenticated?)` | Разбор JSON, для 204 возвращает undefined |
| `request(path, init?, authenticated?)` | Исходный Response, в том числе для изображений |
| `setToken(token)` | Установка или сброс Bearer-токена; этим управляет store/auth.ts |
| `errorText(error)` | Текст ошибки API и ошибок полей для интерфейса |

В `init` передаются обычные параметры fetch. JSON-тело задаётся через
`JSON.stringify`, файлы — через `FormData` без ручного Content-Type.
Для публичных запросов передаётся `authenticated=false`. Клиент добавляет
`X-Requested-With` для Symfony Profiler, учитывает `VITE_API_BASE_URL`,
принимает AbortSignal и по умолчанию ограничивает запрос 20 секундами.

401 действующего токена вызывает `session-expired`: авторизация очищает сеанс,
роутер открывает вход. Поздний 401 старого сеанса не сбрасывает новый токен.
Публичные ошибки входа и активации не завершают другой открытый сеанс.

Тесты адаптеров запускаются командой:

```sh
docker compose run --rm --no-deps node npm test
```

## Пользователи и авторизация

[Вход](http://127.0.0.1:18080/#/login),
[восстановление пароля](http://127.0.0.1:18080/#/forgot-password),
[управление пользователями](http://127.0.0.1:18080/#/admin/users).
Открытой регистрации нет. Первый технический администратор: `admin@example.com`.
Пароль согласован отдельно и в документации не хранится.

Миграция создаёт единственного системного суперадминистратора в новой БД.
Задать ему имя и начальный пароль (запрашивается скрыто) можно один раз:

```sh
docker compose exec php php bin/console app:user:initialize-admin 'Имя администратора'
```

Системную роль нельзя назначить или снять через интерфейс, API или CLI.
Суперадминистратор управляет администраторами; администратор — собой и обычными
пользователями. Блокировка собственной записи запрещена.

Администратор приглашает пользователя по имени и email; остальные поля
необязательны, поля задания пароля нет. Пользователь по письму задаёт пароль
и дополняет профиль, после сохранения становится активным. В списке есть
повторная отправка приглашения. При недоступном SMTP запись сохраняется
неактивной с предупреждением; отправить письмо можно после настройки почты.

Администратор меняет свой профиль и данные обычных пользователей. Изменение
другого администратора запрещено. Обычные пользователи обращаются за изменением
данных к администратору. 2FA отложена.

Все изменения схемы и разовые преобразования данных выполняются только
миграциями Doctrine. Обычные операции интерфейса изменяют данные через ORM.

```sh
docker compose exec php php bin/console doctrine:migrations:diff
docker compose exec php php bin/console doctrine:migrations:migrate
```

## Панель разработчика

[Symfony Profiler](http://127.0.0.1:18080/_profiler/) подключён как
dev-зависимость и включён только в окружении Symfony `dev`.
Нижняя панель отладки отображается на [главной странице Vue](http://127.0.0.1:18080/)
и на [Twig-странице](http://127.0.0.1:18080/server/status). Nginx передаёт
HTML-оболочку `/` и `/index.html`, а также `/_profiler` и `/_wdt` в Symfony.

Symfony отдаёт собранную HTML-оболочку Vue и автоматически вставляет штатную
панель только в `dev`. JS и CSS отдаёт Nginx. Запросы Vue к API передают
`X-Requested-With: XMLHttpRequest`, поэтому панель обновляется данными
последнего AJAX-запроса. Прямая ссылка на профиль запроса также приходит
в HTTP-заголовке `X-Debug-Token-Link`.

В production панель и маршруты профайлера отключены. Статический `dist/index.html`
для Capacitor не изменяется Symfony и не содержит панели.
Инструменты самого браузера открываются через его меню разработчика;
на macOS обычно сочетанием `Option + Command + I`.

## Будущее мобильное приложение

`frontend/capacitor.config.ts` указывает `webDir: dist`. В приложение будет
включена та же сборка Vue; серверные Twig-шаблоны остаются на Symfony.
Native Android-проект и APK пока не создаются. Перед их созданием нужно
согласовать постоянный `appId`, HTTPS-адрес API и CORS. Для хранения Bearer-токена
в Android потребуется адаптер защищённого хранилища Keystore.
Адрес API задаётся через `VITE_API_BASE_URL` при сборке; в браузере по умолчанию
используется тот же origin.

## Подключение к PostgreSQL с компьютера

База доступна по `127.0.0.1:15432`. Порт задаётся переменной `POSTGRES_PORT`
в корневом `.env`; в контейнере PostgreSQL продолжает использовать `5432`.

Для IDE или клиента БД:

- Host: `127.0.0.1`.
- Port: `15432` по умолчанию.
- Database: значение `POSTGRES_DB` из `.env`, по умолчанию `landlordservice`.
- User: значение `POSTGRES_USER` из `.env`, по умолчанию `landlordservice`.
- Password: значение `POSTGRES_PASSWORD` из корневого `.env`.

Порт опубликован только на loopback-интерфейсе компьютера.
После изменения порта применить конфигурацию:

```sh
docker compose up -d --wait database
```

## Локальные данные PostgreSQL

Каталог `var/postgresql` подключён к `/var/lib/postgresql` в контейнере.
В PostgreSQL 18 сам кластер расположен в `var/postgresql/18/docker`.
Данные сохраняются при остановке и пересоздании контейнеров, включая
`docker compose down`. Не удалять `var/postgresql` при обычном перезапуске.

`var/backups` содержит резервные копии. При переносе проекта сохранена
логическая копия всех баз и ролей; прежний Docker volume оставлен для отката.
Оба каталога исключены из Git и Docker build context.
Файлы работающего кластера не следует копировать как обычную резервную копию:
использовать штатный dump или предварительно остановить PostgreSQL.

## Документация пользователей и API

- [HTML-инструкция](http://127.0.0.1:18080/help/users.html) — вход, приглашения,
  восстановление, профиль, фото, управление пользователями и ограничения ролей.
- [Swagger UI](http://127.0.0.1:18080/server/api) — реализованные API-методы.
- [OpenAPI JSON](http://127.0.0.1:18080/server/api/openapi.json) — для интеграторов.

HTML-источник: `frontend/public/help/users.html`. Спецификация генерируется Nelmio
из атрибутов контроллеров/DTO и общей конфигурации; Swagger UI работает с локальными
встроенными ресурсами. Документация обновляется при изменении реализованных сценариев.
Bearer в Swagger вводится через Authorize без префикса; токен не сохраняется между
перезагрузками. Токен приглашения задаётся отдельно как X-Invitation-Token.

## Форматирование

```sh
docker compose run --rm --no-deps node npm run format
docker compose run --rm --no-deps node npm run format:check
docker compose exec -T php vendor/bin/php-cs-fixer fix
```

Prettier и ESLint форматируют собственный код клиента: каждый тег шаблона
расположен на отдельной строке, блоки Vue и логические блоки JS/TS разделены
пустыми строками. Проверка ESLint включена в `./bin/check`. Производные значения
шаблонов выносятся в `computed`; `watch` применяется только для документированных
исключений синхронизации. PHP CS Fixer сохраняет формат методов контроллеров.
