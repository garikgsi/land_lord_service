# Согласованные предметные миграции

Схема согласована владельцем 20 ноября 2026 года. Миграции перенесены из
backend/migration-drafts, namespace DomainMigrations зарегистрирован в Doctrine.
Применённые пользовательские миграции не менялись. Предметные миграции
применены к локальной development-БД после резервного копирования. ORM всех таблиц реализована. Доступны API и интерфейс объектов/арендодателей;
остальные предметные сервисы ещё не реализованы.

| Файл | Состав |
| --- | --- |

| Version20261119215100.php | Коммуникации, поставщики, приборы, установки, история поверок |
| Version20261119215200.php | Показания и проверка их порядка |
| Version20261120120000.php | Вложения договоров и ручные платежи |
| Version20261120130000.php | Месячные начисления и директорские корректировки |

Всего 20 таблиц. Структура и правила: [модель](../../../docs/domain-model-review.md).

objects.reading_day и contracts.contract_type_id обязательны без SQL DEFAULT.
При реализации сервер создания подставляет 25-е число и тип «аренда» соответственно.
Nullable meters.reading_day означает наследование графика объекта.

Одно начисление относится к договору и календарному месяцу. Корректировки содержат
полный набор замещающих параметров и окончательную сумму, включая 0. Актуальная
запись выбирается по created_at DESC, id DESC; корректировки не суммируются.
При отсутствии корректировок используются исходные значения начисления.
SQL не реализует автоматический расчёт, права доступа, жизненный цикл Space
и сальдо: это задачи предметных сервисов. Деньги и площади — NUMERIC без масштаба.

Проверка up/down, повторного применения, связей и ограничений:

```sh
docker compose exec -T php php bin/phpunit tests/Migration/DomainMigrationTest.php
```

Тесты запускают предметный Migrator внутри транзакции отдельной тестовой БД.
Уже применённые предметные миграции откатываются в этой же транзакции перед
проверкой up/down; по завершении исходное состояние БД восстанавливается.
ORM-модели всех 20 таблиц согласованы со схемой, включая точный NUMERIC без масштаба.

Цвет арендодателя: добавочная миграция Version20261120140000 вводит
land_lords.color VARCHAR(7) NULL (#RRGGBB), с CHECK формата. NULL означает
цвет отображения Indigo; значение по умолчанию определяется интерфейсом.
Общий контракт Colorable и trait HasColor можно подключать к другим сущностям
с отдельной миграцией их таблицы. Общей таблицы без внешних ключей не создаём.
