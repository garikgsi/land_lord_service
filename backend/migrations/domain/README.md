# Согласованные предметные миграции

Схема согласована владельцем 20 ноября 2026 года. Миграции перенесены из
backend/migration-drafts, namespace DomainMigrations зарегистрирован в Doctrine.
Применённые пользовательские миграции не менялись. Предметные миграции
применены к локальной development-БД после резервного копирования. ORM всех таблиц реализована. Доступны API и интерфейс объектов/арендодателей;
арендаторы, помещения, договоры и их вложения также имеют API и интерфейс.

| Файл | Состав |
| --- | --- |
| Version20261119215000.php | Справочники Ownership и ContractType, арендодатели, объекты, Space, арендаторы, контакты, договоры |
| Version20261119215100.php | Коммуникации, поставщики, приборы, установки, история поверок |
| Version20261119215200.php | Показания и проверка их порядка |
| Version20261120120000.php | Вложения договоров и ручные платежи |
| Version20261120130000.php | Месячные начисления и директорские корректировки |

Всего 20 таблиц. Структура и правила: [модель](../../../docs/domain-model-review.md).

objects.reading_day и contracts.contract_type_id обязательны без SQL DEFAULT.
При реализации сервер создания подставляет 25-е число и тип «аренда» соответственно.
Nullable meters.reading_day означает наследование графика объекта.

Одно начисление относится к договору и календарному месяцу. Корректировки содержат
полный набор замещающих параметров и окончательную сумму, включая 0. Актуальная
запись выбирается по created_at DESC, id DESC; корректировки не суммируются.
При отсутствии корректировок используются исходные значения начисления.
SQL не реализует автоматический расчёт, права доступа, жизненный цикл Space
и сальдо: это задачи предметных сервисов. Деньги и площади — NUMERIC без масштаба.

Проверка up/down, повторного применения, связей и ограничений:

```sh
docker compose exec -T php php bin/phpunit tests/Migration/DomainMigrationTest.php
```

Тесты запускают предметный Migrator внутри транзакции отдельной тестовой БД.
Уже применённые предметные миграции откатываются в этой же транзакции перед
проверкой up/down; по завершении исходное состояние БД восстанавливается.
ORM-модели всех 20 таблиц согласованы со схемой, включая точный NUMERIC без масштаба.

Цвет арендодателя: добавочная миграция Version20261120140000 вводит
land_lords.color VARCHAR(7) NULL (#RRGGBB), с CHECK формата. NULL означает
цвет отображения Indigo; значение по умолчанию определяется интерфейсом.
Это первоначальное хранение заменено миграцией Version20261121140000 ниже.

Версионирование: Version20261121120000 добавляет valid_from и зеркальные таблицы
land_lords_history, objects_history, renters_history, spaces_history, contracts_history.
Их столбцы совпадают с основной таблицей, плюс valid_to; id сохраняет идентификатор
сущности, первичный ключ — (id, valid_to). При INSERT архив пуст; BEFORE UPDATE
сохраняет OLD целиком только при физическом изменении. Основная запись получает
время UTC с микросекундами; архивная — ту же исключительную верхнюю границу.
Триггер обеспечивает атомарность и при прямом обновлении через Doctrine/SQL.
У прежних записей valid_from NULL: исходное время создания неизвестно.
Исторические таблицы исключены из ORM schema diff; новые столбцы следует добавлять
в обе таблицы одной миграцией. Общий EntityHistoryService читает версии и состояние
на момент времени. Отдельных событий/JSON-снимков и запланированных изменений нет.
contracts.increase_interval_months — необязательный положительный интервал
календарных напоминаний, не автоматических повышений.

Version20261121130000 подключает полные версии ownerships, contract_types,
renter_contacts. У старых строк valid_from неизвестен; новые получают время UTC.
Version20261121140000 переносит цвет из land_lords и land_lords_history в
entity_colors/entity_colors_history. Основная таблица: id INT identity,
entity_type VARCHAR(80) NOT NULL, entity_id INT NOT NULL, color VARCHAR(7) NULL,
valid_from TIMESTAMP(6) NULL; уникальна пара entity_type/entity_id.
История содержит те же столбцы плюс valid_to, PK(id, valid_to).
Discriminator land_lord стабилен и не зависит от имени PHP-класса. Другие сущности
подключаются через Colorable и свой предметный сервис, без нового color-столбца.
У полиморфного владельца нет общего SQL FK: допустимый тип и сохранённый ID задаёт
предметный сервис, публичного API записи произвольной пары type/id нет.
Цвет NULL означает прежний Indigo в UI. Сохраняются все старые окна цветов.
Down пересекает окна имени и цвета и восстанавливает объединённые версии владельца,
в том числе изменения только цвета после перехода на новую схему.
Новая миграция не переписывает ранее применённые миграции.

Version20261121150000 добавляет notifications и notification_deliveries.
Сообщение принадлежит пользователю, due_date выводит его в личный календарь,
read_at — идемпотентная отметка прочтения. Уникальная пара user_id/deduplication_key
защищает от дублей системного события. Доставка db/email/push хранится отдельно,
с уникальной парой notification_id/channel, статусом, попытками и арендой worker.
Это технические записи: payload уведомления неизменен, read_at и состояние очереди
не создают бизнес-версии _history. Обе таблицы входят в обычный резервный дамп.

Version20261121160000 добавляет valid_from и зеркальные _history для meters,
unities, unity_providers. При первом создании архив не заполняется. Изменения
архивируются общим триггером; текущая версия остаётся в основной таблице.
Имеющиеся verification_date предварительно переносятся в meter_verifications
без повторения той же даты. Откат не удаляет сохранённые даты поверок.

Version20261121170000 переносит тип коммуникации из глобального поставщика в
ObjectUnityProvider; уникальна тройка object_id/unity_provider_id/unity_id.
У ObjectMeter появляется необязательный object_unity_provider_id. Триггеры
проверяют совпадение объекта/типа при изменении любой стороны. Legacy unity_id
глобального поставщика nullable, сохранён только для старых полных версий;
в новых API и бизнес-правилах не используется. IDs существующих связей сохранены.
Откат отказывается терять назначения счётчиков или представлять многотипного/
нового поставщика без типа старой одиночной связью.


`Version20261122190000`: пометки `is_deleted` реестров и их зеркальных историй. Исключение периодов договоров учитывает только неудалённые строки. CHECK не допускает пометку подписанного договора. Данные не удаляются; откат может потребовать устранить пересечения периодов, допустимые после удаления черновиков.
